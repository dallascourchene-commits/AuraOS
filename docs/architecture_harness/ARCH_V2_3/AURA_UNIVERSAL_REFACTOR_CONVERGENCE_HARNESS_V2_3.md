# AURA Universal Refactor Convergence Harness (ARCH) v2.3

## Recursive, provenance-governed continual refactor harness with mediated coordination, non-malleable authority, commit-time authorization, bounded JSpace working state, and proof-carrying evolution

**Status:** Current repository harness architecture standard; human-governed and non-self-authorizing  
**Date:** 2026-08-07  
**Supersedes:** ARCH v2.2 as the forward standard  
**Inheritance:** Every load-bearing v1/v2/v2.1/v2.2 guarantee remains mandatory unless v2.3 explicitly strengthens it  
**Migration:** In-flight bounded PRs remain on their accepted capsule unless a human explicitly migrates them  
**Constitution:** no second truth, memory, routing, verification, persistence, policy, authority, governance, merge, communications/control, or shared-workspace plane

---

# 0. Executive decision

ARCH v2.3 consolidates ARCH v2.2 rather than replacing its architecture. v2.2 established exact-head continuity, recursive programmable workers, persistent typed state, governed continual harness evolution, QDKT/DREAM/DIKWP learning, provenance, canaries, rollback, and independent verification. v2.3 closes the next failure class: multiple individually bounded workers can still coordinate through hidden channels, launder authority through derived content, commit durable effects under stale approvals, manufacture apparent corroboration, or turn an advisory shared workspace into a de facto second control plane.

v2.3 adds six hard rules:

1. **All inter-agent coordination is declared and harness-mediated.** Explicit messages, shared files, caches, status fields, timing, ordering, retries, tool-call behavior, and JSpace are all possible channels.
2. **Authority is origin-bound and non-malleable.** Content, repetition, summarization, trusted-tool echoes, consensus, or derived state cannot mint or upgrade authority.
3. **Durable effects require commit-time authorization.** Earlier approval is insufficient when head, lease, witness, dependency, effect binding, or eligibility has changed.
4. **Verifier independence is proved, not counted.** Correlated workers cannot masquerade as independent corroboration.
5. **AuraJSpace is a bounded advisory working set.** It is reconstructable from canonical state and can never become truth, policy, routing ownership, verifier status, patch authority, memory authority, or merge authority.
6. **Enforcement lives below model persuasion.** Prompts, model monitors, self-critique, and model-written constitutions are advisory; deterministic gates own admission, revocation, durable commit, rollback, and stop.

The complete loop is:

```text
objective
  → exact-head orientation
  → machine-authoritative continuity capsule
  → frozen objective / non-objectives / threat model / decisions / invariants
  → declared channels + minimum task-conditioned leases
  → bounded recursive context / workers / optional JSpace working set
  → governed patch transaction
  → exact proof + verifier-independence assessment
  → experience / QDKT / DREAM / DIKWP learning proposal
  → isolated harness-evolution evaluation when triggered
  → external review / finding triage
  → commit-time authority revalidation
  → durable promotion or replan/refusal
  → provenance / cleanup / terminal receipt
  → READY_FOR_HUMAN_REVIEW
  → human disposition
```

No autonomous merge.

# 3. Recursive context and minimum fidelity

Long-horizon context is addressable typed state, not a transcript. Typical handles include objective, current head, active root cause, mandatory evidence, failed attempts, proof frontier, source slices, dependency closures, and unresolved review findings.

Allowed operations may include bounded `hydrate`, `slice`, `map`, `compare`, `trace_back`, read-only `join`, and `summarize_with_origin`.

The following cannot be evicted merely to save tokens:

- repository/base/head identity;
- objective/non-objectives/current phase;
- authority boundary and active lease ceilings;
- canonical owners;
- accepted input/threat model;
- frozen decisions and invariants;
- current open root causes/findings;
- rejected approaches and retry conditions;
- last known green/rollback point;
- exactly one authorized next action;
- durable-promotion status;
- v2.3 delegation, communication, JSpace, commit-authorization, and independence state.

Derived summaries carry their source/origin/authority ceilings. Representation may change; authority may only stay equal or decrease.

Required channel properties:

- payload is typed and canonicalized;
- origin and authority labels propagate non-malleably;
- size/rate/queue/fan-out/retention are bounded;
- delivery or rejection emits a receipt;
- a channel cannot mint capability, policy, verifier status, or merge readiness;

The threat model includes **storage, timing, and behavioral channels**. Shared files, filenames, caches, task status, logs, timing/retry cadence, ordering choices, tool-call patterns, JSpace packets, and other shared events can act as covert communication media. Model wardens may assist detection but never become the sole enforcement boundary.

# 6. Non-malleable origin-bound authority

Authority is minted only by canonical policy/human/governance owners and admitted through deterministic capability boundaries.

Hard rules:

```text
content does not grant authority
repetition does not grant authority
summarization does not upgrade origin
trusted-tool echo does not upgrade origin
consensus does not grant authority
reviewer count does not establish independence
derivation cannot raise authority

```

When content is transformed, the most restrictive relevant origin/authority label propagates. A trusted tool processing untrusted input does not magically convert that input into trusted authority. Manufactured corroboration from a shared origin does not count as independent elevation.

# 7. AuraJSpace as bounded deliberative working state

Aura already implements `aura_jspace_codec.py` as an explicit deterministic advisory codec:

```text
codec: AURA_JSPACE_CODEC_V0
packet family: J0
default active limit: 25
patch authority: none
vsa patch authority: false
```

ARCH v2.3 admits JSpace as a **bounded advisory deliberative working-set projection** attached to the live refactor/capsule state.

A v2.3 projection carries:

```yaml
projection_id:
codec_version: AURA_JSPACE_CODEC_V0
workspace_id:
head_sha:
phase_hash:
packet_digest:
active_limit: <= 25
source_refs:
origin_refs:
freshness:
authority_class: ADVISORY_NONE
patch_authority: false
persistent_truth: false
reconstructable: true
expires_at:
```

Rules:

- current default and policy ceiling is 25 active concepts; lowering it is allowed;
- overflow cannot silently increase authority or hide required minimum-fidelity state;
- secret/credential material is forbidden;
- every item remains traceable to canonical source/origin references;
- head/workspace/phase mismatch makes the projection stale;
- stale state is reconstructed from canonical capsule/route/evidence or disabled;
- JSpace cannot become a second memory, router, planner, verifier, policy, authority, governance, or communications plane;
- persistent lessons are promoted only through existing canonical learning/provenance owners;
- any action influenced by JSpace must rehydrate exact evidence and pass normal lease/proof/commit authorization.

Anthropic's July 2026 J-space is a different mechanism: an emergent neural activation subspace identified using a Jacobian-based lens. Their reported small selective workspace and typical `k <= 25` sparsity is useful architectural precedent for a bounded working set, but it does **not** make Aura's software codec neurally equivalent. The shared number 25 is treated as an empirical/design correspondence, not a universal cognitive law.

```yaml
witness_id:

capability_lease_digest:

```

Before commit/publish/persist/promote or another durable effect, prove:

1. exact current repository/head/workspace/resource identity still matches;
2. the authority witness remains fresh and unrevoked;
3. the capability lease is unexpired and still eligible;
4. the witness is causally prior to the effect it authorizes;
5. planned effect digest and candidate effect digest match the authorized effect class/scope;
6. relevant dependencies and accepted threat model have not changed;
7. required proof is fresh;
8. verifier-independence requirements still hold;
9. required human/governance disposition is present.

If any binding changed: **replan, refresh/rebind, or refuse**. Endpoint success is a utility observation, not an authorization property.

# 10. Governed continual harness evolution

The harness may learn and improve mutable surfaces such as supplemental prompts, memories, reusable procedures/skills, worker specs, routing hints, evaluation heuristics, and bounded orchestration configuration only when the controlling policy marks them mutable.

Constitutional surfaces remain outside self-edit authority, including truth order, canonical ownership, authority boundaries, hard security invariants, promotion/rollback gates, evaluator independence, human-review requirements, and merge policy.

Evolution pipeline:

```text
verified experience/failure
  → root-cause grouping
  → QDKT competence update
  → DREAM/Dreamlight counterfactual rehearsal
  → DIKWP evidence classification
  → minimal HarnessEvolutionProposal
  → predicted effect + falsification condition
  → isolated candidate
  → regression + adversarial + transfer + metaproductivity evaluation
  → independent disposition
      REJECT / ARCHIVE / CANARY / PROMOTE_LOCAL / PROMOTE_PROJECT / PROMOTE_GLOBAL / ROLLBACK
  → attestation/provenance receipt
```

A candidate cannot edit its evaluator, expected benchmark outputs, its own failure history, constitutional gates, or the rules deciding its promotion. Immediate task improvement is not automatically preferred over long-run metaproductivity.

# 11. QDKT, DREAM, DIKWP, Attempt Archive, and provenance

**QDKT** records structured competence/learning observations and retrieval usefulness. It can nominate crystallization candidates; it cannot crystallize executable policy automatically.

**DREAM/Dreamlight** selects useful experience and performs counterfactual rehearsal. Its scores are advisory. Counterfactual replay is not production proof.

**DIKWP** separates:

```text
DATA        exact event / receipt / trace
INFORMATION normalized context/failure/route/cost
KNOWLEDGE   replicated evidence-supported pattern
WISDOM      bounded recommendation under stated conditions
PURPOSE     alignment with authorized objective/governance
```

Semantic stage is not authority.

**Attempt Archive / Crucible / ArenaExperience** preserve rejected approaches, failures, denials, superseded work, successful proof, and reusable verified experience so the system does not repeatedly rediscover failure.

**Attestation/intellectual provenance** records causal execution and evolution lineage, including upstream project/repository/commit/path/license/copyright relation and whether use is `ORIGINAL`, `INSPIRED_BY`, `ADAPTED_FROM`, or `VENDORED_FROM`. Provenance is a projection of causal evidence, not a second truth plane.

# 15. Security and adversarial suite

v2.3 preserves all v2.2 tests and adds the following families.

## 15.1 Recursive execution

- child asks for authority above parent/workspace;
- out-of-lease mutation;
- spoofed parent/sibling identity;
- cross-worker prompt injection;
- depth/fan-out/cost overflow;
- descendant survives cancellation;
- stale-source proof;
- correlated agents falsely counted as independent.

## 15.2 Kernel/runtime

- filesystem/symlink/path escape;
- network egress beyond policy;
- secret/environment laundering;
- orphan process;
- checkpoint against changed head;
- revoked capability restored from checkpoint;
- malicious serialized state/native execution bypass.

## 15.3 Continual learning and memory

- repository text attempts global memory write;
- prompt injection becomes harness policy;
- untrusted memory summarized or tool-echoed into higher trust;
- manufactured corroboration;
- candidate edits evaluator/benchmark/failure history;
- local success self-promotes globally;
- rollback leaves contaminated descendants;
- project-specific lesson contaminates unrelated project.

## 15.4 Provenance/evolution

- adapted code labeled original;
- upstream commit/path/license omitted or altered;
- attribution rewritten by derived summary;
- benchmark overfit;
- token reduction by omitting required evidence;
- faster result by skipping verifier;
- candidate and evaluator share hidden mutable state.

## 15.5 Covert coordination / second plane

- workers coordinate through shared file content or filenames;
- cache keys encode commands;
- timing/retry cadence encodes hidden state;
- benign tool-call ordering encodes coordination;
- task status becomes command bus;
- JSpace becomes hidden mailbox;
- model-based warden misses covert channel;
- worker creates shadow router/verifier/policy/memory/control store;
- communication metadata survives revoked lease.

## 15.6 Authority and commit boundary

- summary/trusted-tool echo/manufactured corroboration laundering;
- approval valid during planning but revoked before durability;
- head changes after verification;
- planned and committed effect differ;
- lease path matches but exact effect does not;
- endpoint reports success while authorization is stale;
- rollback leaves derived authoritative state.

## 15.7 JSpace and independence

- JSpace becomes patch/routing authority;
- stale phase/head accepted;
- secret material enters projection;
- active-limit overflow handled unsafely;

- projection survives capsule invalidation as truth;
- same poisoned origin counted repeatedly;
- same session/model forks counted as independent without disclosure;
- majority suppresses exact counterexample;
- fabricated verifier identities/receipts.

# 16. Memory and rollback lifecycle

Every durable learning object has policy for:

| Phase | Control |
|---|---|
| Write | origin, principal, evidence, authority ceiling, scope |
| Store | version, provenance, retention, integrity, tenant/project boundary |
| Retrieve | relevance + truth/authority class + freshness + source closure |
| Execute/use | least privilege; memory cannot grant authority |
| Share/propagate | audience, purpose, origin propagation, disclosure bounds |
| Forget/rollback | descendants identified; revocation/repair receipt |

Rollback applies causal contamination closure to derived memories, summaries, JSpace-derived artifacts, learning candidates, and propagated state. Deleting one record is insufficient if its descendants remain influential.

# 17. Evaluation and convergence

A candidate is assessed on:

- **correctness:** task success, regression, invariant preservation, grounding, proof completeness;
- **efficiency:** tokens, bytes hydrated, calls, cost, latency, duplication;
- **reliability:** repeated runs, model substitution, fresh-session continuation, crash/restart, stale-head rejection, cleanup;
- **security:** authority escalation, laundering, covert channels, memory poisoning, replay, secret/network escape, commit freshness, rollback completeness;
- **learning quality:** repeated-error reduction, false crystallization, held-out transfer, interference/forgetting;
- **metaproductivity:** future localization time, counterexample quality, descendant improvements, orientation cost, proof reuse, rejected-approach avoidance.

Production remains `PRODUCTION_CHAMPION`; candidates remain separate as canaries/experiments/rejected archives until independently promoted.

The machine-readable default weights and rollback triggers are in `aura_arch_v2_3_default_policy.json`.
