# Aura Observatory — Bulk-Intent Routing and Architecture Tour

## Identity

The deterministic bulk-intent surface is the **Aura Observatory**.

It answers:

> What did Aura understand, how did she route it, what context did she select,
> and where does authority stop?

It is not the Learning Arena. The **Learning Arena / Crucible** consumes complete,
verified Arena experiences and produces proposal-only crystallization packets.

## Observable routing path

```text
ordinary bulk human intention
  → deterministic local lexical addressing
  → lightweight local tag extraction
  → DIR → ASP → CLASS → SUBJ → VOICE → STEM
  → machine FST hard-gate routing
  → CODEMAP localization
  → bounded topology
  → compressed handoff to a replaceable worker
```

No LLM is called during these stages.


## Usable workspace

The Observatory is not locked to a presentation sequence. A person may:

- enter or edit any bulk natural-language intention;
- compile repeatedly without manually writing JSON or slot names;
- inspect any routing view in any order;
- view all evidence together;
- inspect the bounded CODEMAP topology;
- copy the compressed worker handoff;
- copy or export the sanitized trace;
- open the bounded intention in a clean Human Agent workflow;
- preserve the question as pre-experience lineage for the Learning Arena.

The optional suggested tour explains each stage but grants no authority.

## Lexical addressing

The local English codebook contains:

```text
4096 primitives
12-bit addresses
```

Known words use their stored address. Unknown words use Aura's deterministic checksum
fallback. The codebook is a stable addressing substrate; it does not provide complete
natural-language understanding or execution authority by itself.

## Local tags and LEXC

The Observatory displays matched text for operation, domain, target, and expected output.
It also exposes relevant `aura.lexc` layers and a candidate six-slot route where one can be
constructed.

The candidate LEXC route is explanatory. The machine Arena FST remains the operative
hard-gate router.

## Six-slot packet

```text
DIR → ASP → CLASS → SUBJ → VOICE → STEM
```

| Slot | Software meaning |
|---|---|
| `DIR` | route or lifecycle direction |
| `ASP` | bounded execution aspect |
| `CLASS` | classified intent/effect class |
| `SUBJ` | target artifact and scope |
| `VOICE` | model and verifier policy |
| `STEM` | terminal operation |

VSA bindings remain advisory after hard guards and have no patch authority.

## Machine FST symbols

Input symbols:

```text
I: intent
A: artifact
X: action
S: scope
R: risk
G: grounding
T: test state
Q: quality policy
C: cost/model policy
```

Output symbols:

```text
O: selected route
M: model policy
K: context class
E: routing reason
V: verifier requirement
```

Hard gates run before weighted alternatives. Soft ranking cannot override missing
grounding, tests, approval, or unresolved-risk requirements.

## Handoffs

### Observatory → Human Agent Arena

The adapter opens a clean Human Agent workflow and imports:

- the compiled objective;
- localized files and symbols;
- source spans and hashes where present;
- focused tests where present;
- six-slot and route lineage;
- a bounded topology summary;
- compressed worker context.

It clears stale showcase evidence first. It never stages or applies a patch.

### Observatory → Learning Arena

A raw intention is not learning evidence. The Observatory creates only:

```text
AWAITING_VERIFIED_EXPERIENCE
eligible_for_crucible: false
```

The required path is:

```text
governed Arena execution
→ verifier evidence
→ OutcomeVector
→ ArenaExperience V3
→ TRAIN / VALIDATION / SHADOW
→ CRYSTALLIZATION_PROPOSED
→ VERIFIER_AND_HUMAN_REVIEW
```

## Provenance boundaries

Keep these distinct:

1. Anishinaabemowin-derived governance alignments;
2. the Athabaskan-inspired six-slot software ordering contract;
3. Aura's machine-oriented FST routing language.

Do not flatten them into one generic “Indigenous grammar.”

## Always-visible authority boundary

Admitted before an LLM:

- parse and sanitize local text;
- assign lexical addresses;
- classify routing features;
- apply FST hard gates;
- localize CODEMAP candidates;
- prepare bounded context and handoffs.

Blocked:

- secret disclosure;
- hidden chain-of-thought capture;
- full-topology transfer;
- visual or VSA patch authority;
- automatic source mutation;
- automatic grammar promotion;
- automatic commit, push, pull request, or merge.

## Claims

Use:

- Aura accepts ordinary bulk intention.
- The pre-LLM routing trace is deterministic and local.
- The LLM is a replaceable worker receiving bounded direction.
- The Observatory explains intent and architecture.
- The Learning Arena learns only from verified experience.

Avoid:

- claiming the 4,096-word codebook alone fully understands language;
- claiming every unknown word is semantically understood;
- treating topology as source authority;
- saying an Observatory intake is already a learned experience;
- saying Aura automatically promotes grammars or merges code.
