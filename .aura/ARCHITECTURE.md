## 1. Architectural identity

AuraOS — Augmented Universal Reasoning Architecture — is a sovereign, local-first, Arena-based cognitive operating substrate.

It is not:

- a single LLM;
- a conventional chatbot;
- a monolithic autonomous agent;
- a visual wrapper around an external model;
- a framework where semantic similarity can authorize changes;
- a system where planning, execution, proof, and governance are collapsed into one output.

The canonical end-to-end flow is:

```text
HUMAN OR COMMUNITY OBJECTIVE
  → lexical address and structured intent
  → DIR → ASP → CLASS → SUBJ → VOICE → STEM
  → semantic LEXC and machine WFST admission
  → capability discovery and ownership resolution
  → exact repository/domain grounding
  → bounded Arena and revocable leases
  → deterministic tools and optional external workers
  → staged proposal or action
  → tests, verifiers, and relational governance
  → authorized human/community decision
  → receipts, telemetry, experience, and review-gated learning
```

> **Meaning may guide discovery. Only exact grounded evidence and authorized governance may grant authority.**

## 2. Provenance and design boundaries

Aura originated as a locally controlled Anishinaabemowin learning system. This shaped persistent architectural priorities:

- local operation and sovereignty;
- data minimization;
- purpose-limited sharing;
- inspectable memory and provenance;
- explicit consent and revocable authority;
- human, speaker, teacher, professional, and community governance;
- bounded external egress;
- refusal to treat model convenience as authority.

## 3. Bilateral live-repair and Spatial Foundry B11–B15

The final bilateral-intent phase composes retained owners into one bounded field-repair path:

```text
confirmed bilateral contract + exact release identity
  → explicit time- and event-bounded incident capture
  → canonical privacy sanitization
  → digest-bound IncidentReplayPacket
  → ArenaAttemptArchive durable evidence
  → Runtime Profile V2 exact reproduction
  → positive + negative + preservation + fault proof
  → bounded repair hypotheses under an eight-attempt budget
  → Surgeon for local defects / Council V3 for structural defects
  → isolated local or canary preview
  → exact last-verified technical rollback when pre-authorized
  → canonical U7 P0 → P1 → current reproof
  → explicit human/community disposition
  → Relationship Experience and governed QDKT observation
  → projection-only Showcase / Spatial Foundry
```

Canonical ownership remains unchanged:

- `aura_arena_experience.sanitize_experience_payload` owns experience-payload sanitization;
- `aura_arena_attempt_archive.ArenaAttemptArchive` owns durable attempt and replay evidence;
- `scripts.aura_runtime_profile_v2_adapter.run_runtime_profile_v2` owns exact runtime proof;
- `aura_unified_memory_continuity_learning` owns P0, P1, current reproof, disposition, Relationship Experience, and QDKT admission;
- `aura_showcase_live_repair_server` composes the existing Showcase server and adds only bounded routes and a projection surface;
- `aura_bilateral_live_repair_foundry*` is an adapter family, not a new truth, policy, memory, verifier, rollback-authority, Construction, Crucible, or learning plane.

The incident marker is retained separately from the rolling event deque so bounded retention cannot evict the marked failure. Finalization, expiry, and service closure scrub both the deque and separately held marker from active memory. The full already-sanitized replay packet is retained as exact canonical JSON inside Attempt Archive so archive key redaction cannot alter digest-bearing safe fields.

Runtime proof is accepted only when it independently matches the incident packet’s intent, confirmation, Semantic Ledger, guardrail, revision, repository-head, source-tree, runtime-profile, and verifier identities. Repair readiness additionally requires positive, negative, preservation, fault-injection, adjacent-regression, repository-cleanliness, and independent-verifier gates. Repeated failed hypotheses remain forbidden across service restarts.

B13 does not introduce production hot-swap authority. Preview and technical rollback are isolated, require an exact last-verified digest, and permit a restore only through a trusted in-process adapter with prior authorization. Browser request bodies cannot manufacture rollback or U7 authority objects.

The Spatial Foundry presents confirmed intent, negative intent, guardrails, runtime evidence, failed attempts, minimized counterexamples, P0/P1/current reproof, human/community disposition, and exact source/receipt drill-down. It remains projection-only: visual position, color, proximity, or connection never becomes canonical truth or authority.

Final internal review is bound to Aura’s retained Review Learning harness, which executes Architect, Council V3, Surgeon, Capability Connectome, Emergent Properties, Coding Waboose, and Crucible over the exact branch range. Its receipt is review evidence only and must preserve all mutation, publication, merge, deployment, professional, physical-work, and learning-promotion authorities as false.
